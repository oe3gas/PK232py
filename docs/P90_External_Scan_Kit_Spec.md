## Anlass

Ein anderer Funkamateur besitzt nach eigenen Angaben **12 PK-232 mit
verschiedenen Firmwareständen** und ist bereit, den Scanner laufen zu lassen
und die Ergebnisse zurückzuschicken. Ziel: die Befehlsmatrix (P88) um weitere
Firmwarestände erweitern, ohne dass wir die Geräte selbst haben.

## Befund

- `tools/pk232_fw_scan.py` importiert heute Teile von PK232PY
  (`serial_manager._WAKEUP`, `_BANNER_MARKERS`, `escape_converse()`,
  `verbose_line()`, den Matrix-Leser). Ohne das ganze Repo läuft er nicht.
- `--update-matrix` schreibt direkt in unsere Matrix — beim externen
  Betreiber gibt es keine.
- Die Geräte des Betreibers sind **nicht** in unserem Testaufbau: Sie können
  an Funkgeräten hängen, eine Pufferbatterie haben (eigene Einstellungen,
  evtl. andere Baudrate, 7 Bit, EXPERT ON, ECHO OFF …) und sind sein
  Eigentum. (P89b: auch ohne Batterie behält ein TNC seine Einstellungen über eine kurze Pause; „Werkszustand“
  entscheidet nur die Banner-Zeile `… is using default values.` - `constants.is_factory_banner()`, im Kit
  eingebettet wie `verbose_line()`.)

## Teil A — Das Kit: ein ZIP, ohne Repo lauffähig

`tools/build_scan_kit.py` erzeugt `dist/pk232_scan_kit_<datum>.zip` mit:

| Datei | Inhalt |
|---|---|
| `pk232_fw_scan.py` | eigenständige Fassung: die benötigten Teile aus PK232PY **beim Bauen** hineinkopiert (generiert, Kopfkommentar „generated by build_scan_kit, do not edit"); Befehlsliste und Arten aus der Matrix als eingebettete Tabelle |
| `requirements.txt` | nur `pyserial` |
| `README_DE.md`, `README_EN.md` | Anleitung (Teil C) |
| `run_scan.bat`, `run_scan.sh` | fragen Port und Baudrate ab, starten den **sicheren** Lauf |
| `device_info.txt` | Formular je Gerät (Teil B) |

Ein Test baut das Kit und lässt den eingebetteten Scanner in einer leeren
Umgebung (nur Standardbibliothek + pyserial-Stub) im `--selftest`-Modus
laufen.

**Commit:** `tools: build_scan_kit - standalone scanner for external operators`

## Teil B — Was je Gerät zurückkommt

Der Scanner legt je Lauf einen Ordner `scan_<release>_<seriennr|n>/` an:

- `banner.txt` — Einschaltbanner **wörtlich** (Release, Version, PACTOR s/n …)
- `scan.csv` — Ergebnis je Befehl (wie heute, mit `release`, `date`)
- `debug.log` — Rohmitschnitt
- `settings_before.txt` — Ausgabe von `DISPLAY` vor dem Scan (zeigt
  eigene Einstellungen bei Geräten mit Pufferbatterie)
- `device_info.txt` — vom Betreiber auszufüllen: Modell (PK-232 /
  PK-232MBX / mit DSP), EPROM-Beschriftung, Platinenoptionen (PACTOR,
  Mailbox, 2400-Bd-Modem), Pufferbatterie ja/nein, Bemerkungen

Am Ende: `results_<rufzeichen>_<datum>.zip` mit allen Ordnern.

**Commit:** `tools: per-device result folder and device_info form`

## Teil C — Sicherheit beim fremden Betreiber

- **Standard ist der sichere Lauf** (nur Parameterabfragen, wie T179). Die
  riskanten Befehle aus P89 sind im Kit **nur** mit `--all` möglich, mit
  der Betreiberbestätigung aus P89 Teil A.
- **Gerät so zurücklassen, wie es war:** vor dem Scan `OPMODE`, `EXPERT`
  und alle vom Scanner berührten Werte lesen, danach wiederherstellen; am
  Ende Vergleich `DISPLAY` vorher/nachher im Log, Abweichungen deutlich
  melden.
- **Kein `MYCALL` setzen**, kein `RESET`, kein `REINIT` im sicheren Lauf.
- `RESTART` wird verwendet (nicht destruktiv, trennt aber Verbindungen) —
  README sagt das.
- Baudrate: `--baud`; README erklärt Autobaud (`*`) und dass Geräte mit
  Pufferbatterie abweichende Schnittstellenwerte haben können.
- README nennt ausdrücklich: Funkgerät abklemmen oder Dummy-Load; welche
  Dateien zurückkommen; dass die Ergebnisse in ein öffentliches
  GitHub-Repo einfließen und mit seinem Rufzeichen als Quelle vermerkt
  werden — mit der Bitte um Einverständnis.

**Commit:** `tools: scan kit safe defaults and restore of the device state`

## Teil D — Import auf unserer Seite

`tools/import_external_scan.py results_<call>_<date>.zip`:

- Neue Releases (Bannerformat `DD.MMM.YY`) werden als neue Spalten
  `fw_/ev_/fx_<release>` angelegt; Gerätebezeichnung extern
  (`ext:<call>:<seriennr>`), **nicht** in `DEVICES.md` (das bleibt unser
  Inventar).
- Zellen nur füllen, wo `?`; Beleg `ext <call> <date> <file>`.
- **Gleiches Release, anderes Ergebnis** als bei uns oder bei einem anderen
  Gerät desselben Releases → nichts schreiben, Liste ausgeben (könnte
  Hardware-Variante oder Messfehler sein).
- Rohdateien unverändert nach `docs/reference/external/<call>/…` (erst
  nach Einverständnis des Betreibers committen).
- `device_info.txt` → eine Zeile in `docs/reference/external/devices.md`.

**Commit:** `tools: import_external_scan merges external results into the matrix`
